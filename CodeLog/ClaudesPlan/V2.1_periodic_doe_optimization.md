# V2.1 DOE Optimization: Periodic BCs + Granule Count Tuning

## Problem
The current DOE generator targets N=500 granules with wall boundaries, but:
1. Wall artifacts bias packing structure (20% exclusion zone wastes domain)
2. N=500 is more than needed for periodic BCs where there's no boundary exclusion
3. Domain size doesn't account for periodic minimum-image constraint
4. Extreme R_f/R_i ratios can produce wildly different effective N

## Changes to `generate_doe.py`

### 1. Switch to periodic BCs
- Add `boundary_mode: "periodic"` to BASE config
- Set `boundary_exclusion: 0.0` (forced to 0 for periodic anyway)

### 2. Reduce N_TARGET from 500 to 250
- With periodic BCs, no boundary exclusion means the full domain contributes
- 250 granules at fixed density gives ~2x speedup (pair count scales ~linearly with N)
- Statistical convergence: 250 granules gives ~6% relative error on volume-averaged quantities

### 3. Physics-aware domain sizing
New `compute_domain_size` enforces three constraints:
- **N_target**: L = (N/density)^(1/3) as before
- **Minimum image**: L > 2 * (2*r_bound_max + L_max) for cKDTree periodic correctness
- **RVE size**: L > 4 * d_max to capture bulk packing statistics

Takes max of all three.

### 4. Cap N to avoid blowup from extreme size ratios
- When R_f << R_i (or vice versa), the small-granule population can explode
- Add N_MAX = 600 cap; if estimated N exceeds cap, shrink L and warn
- This bounds worst-case compute while flagging potentially under-resolved runs

### 5. Reduce Ngrid_3d from 80 to 60
- 60^3 vs 80^3 = 3.4x faster field rendering
- Sufficient resolution for the scalar metrics we extract

## Expected Speedup
- N reduction: ~2x
- Ngrid reduction: ~3.4x on field computation (minor fraction of total)
- No wall force loop: small savings
- **Net: ~2x faster per run, ~4500 CPU-hrs saved across 500-run DOE**
