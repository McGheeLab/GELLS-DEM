# V3.6 — the substrate the solver does not see

## Why this version exists

V3.5 ended with two things the engine *models* but the solver never *feels*, and
they are the same defect twice:

1. **A wall contact is a contact everywhere except in the implicit step.**
   `contact_stiffness_per_granule` sums `2 E_s a` over the **pair** contact list.
   Wall contacts are applied inline in `gather_2d` / `gather_3d` / `reference.py`
   and never reach that list, so a granule held only by a wall gets
   `gamma = drag_scale * r` — no semi-implicit damping at all — and oscillates
   about its contact equilibrium (±0.015 µm measured in the single-granule test).
   Before V3.5 this was invisible, because `boundary.wall_clamp` held every floor
   granule 0.5 µm clear of the wall and **no granule was ever in wall contact**.
   Changing the default to `contact` made wall contacts real, and made this gap
   real with them.

2. **A cell standing on another cell is given a granule's substrate.**
   `motor_clutch_force` is evaluated with `E = gs.E_gran[i]` for every cell on
   granule `i`, whatever it is actually anchored to. Cells above the monolayer
   are counted (`cell_stacking_max`) but pull as if they were touching hydrogel.

Both are "the force law has a substrate the numerics never asks about". Fixing
(1) was blocked until V3.5 Phase 5 retired the `reference.py` freeze — the wall
stiffness has to be accumulated in **both** twins' gathers, which is exactly the
edit the old fixture gate forbade.

| Phase | Deliverable |
|---|---|
| **1** | Wall contact stiffness reaches the semi-implicit step (both twins) |
| **2** | `dynamics.substep` — `dt` becomes a coupling interval, and the mechanics is substepped from the stiffness number |
| **3** | `gels/celltypes/` — cell types as objects, traction as a stress, and cell strain energy |
| **4** | `cells.stacking` — cells crawl on cells, with an emergent granule preference |
| **5** | `gels/convergence.py` — a convergence detector, plus the shadow harness that calibrates it |
| **6** | Documentation sweep: ARCHITECTURE.md, README.md, the V3.3-backlog bookkeeping |

Phase 2 was not in the version as planned. It was added after the user asked
whether `dt` could be chosen from the state of the system rather than fixed, and
it belongs to the same subject: a third thing the solver could not see, this
time about its own step.

**Explicitly deferred, with the reason:** the HTML viewer adapter (V3.3 Phase 7).
`pipeline/live_view.py` and `viz2/compare_runs.py` already cover watching a run
and comparing several, and the adapter's value is a gallery for runs that do not
exist yet. It is deferred, not dropped.

## Phase 1 — wall contact stiffness

### The change

`jkr_force_from_overlap` already returns `(F, a)` at **every** wall call site in
both twins — 3 in `reference.py` 2D, 3 in `reference.py` 3D (box + cylinder),
2 in `contact2d.gather_2d`, 3 in `contact3d.gather_3d` — and **`a_w` is
discarded at all of them**. So the stiffness is free: `k_wall_i += 2 E_s a_w`,
with `E_s = gs.wall_Estar[species] * 1e-3` (Pa → nN/µm²), the identical
conversion `contact_stiffness_per_granule` applies to `E_star`.

Carried on `gs.wall_stiffness` (float64, length N), written by the force
evaluation and read by `contact_stiffness_per_granule(gs, contacts)`, so the two
call sites in `step()` do not change and every consumer of that function
(the semi-implicit step) picks it up at once.

### Why this is not a free parameter

The semi-implicit argument is unchanged and is the whole justification: at the
fixed point `F = 0`, so the step is zero for any drag. Adding a term to `gamma`
therefore **cannot move the equilibrium** — it changes the transient only. The
same argument `contact_semi_implicit` and `gradient_flow: damped` both rest on.

### What to measure, not assume

* the single-granule-on-a-floor oscillation amplitude, before and after
  (V3.5 measured ±0.015 µm; the claim is that it goes to the contact law's own
  equilibrium);
* `frac_velocity_clipped` and `overlap_clip_fraction` on a sedimented bed
  pressed into a wall — the V3.2 projection metrics are the honest witness;
* the handoff ratio and `free_force_percentile` on the wall-supported bed, since
  a wall granule's residual is the term V3.5 could not remove.

### Tests — `tests/test_wall_stiffness.py`

1. **The twins agree.** `gs.wall_stiffness` from `reference.py` and from the
   compiled gather, on a wall-pressed bed, exact.
2. **It is zero when it should be.** Periodic boundaries, and a `centre`-packed
   bed off the walls: identically 0, so no run that never touches a wall changes.
3. **The fixed point is untouched.** Same bed, `contact_semi_implicit` on and
   off, run to force balance: same equilibrium positions to tolerance.
4. **The oscillation is gone.** A single granule dropped on the floor: the
   position trace's late-time peak-to-peak amplitude falls by the predicted
   factor.
5. **Cylinder and free-top geometries** are covered, since the cylinder wall is
   a separate call site.

## Phase 2 — `dt` is a coupling interval, not an integration step

### The finding, measured before anything was built

`contact_semi_implicit` takes `vel = F/(gamma + dt k)`. At the fixed point
`F = 0`, so the equilibrium is exact for any `dt` — that is what makes it
unconditionally stable and why V3.2 adopted it. But the **rate** is
`F/(gamma + dt k)` where the overdamped rate is `F/gamma`, so with

    S = dt k / gamma

every granule moves `(1 + S)` times too slowly.

At the shipped `dt = 0.5 h` on a 2D cell-seeded bed, **S averages 41 and reaches
88, with 90 % of granules above 1**. Consequences, 24 h, 3 seeds, with the
velocity cap lifted so it cannot confound:

| `dt` (h) | `F_mean` (nN) | `disp_func` (µm) | `overlap_clip_fraction` |
|---|---|---|---|
| 0.5 | 136 ± 21 | 11.3 ± 1.3 | 0.062 |
| 0.1 | 85.7 ± 3.9 | 25.2 ± 2.0 | 0.038 |
| 0.02 | 40.1 ± 5.1 | 36.8 ± 0.2 | 0.000 |
| 0.005 | 29.7 ± 2.3 | 48.4 ± 3.7 | 0.000 |

At `dt = 0.25` and `0.1`, `max_overlap_ratio` reads `0.150 ± 3e-16` — exactly
`max_overlap_frac`, i.e. the bed is pinned on the geometric rail.

### And the equally important negative result

**A passive run does not need this.** A gravity bed run at `dt = 0.5 h` has a
bed height 0.22 µm out of 444 from the same bed at `dt = 0.005 h` (0.05 %) and a
`phi_bed` 0.0003 from it — whether the packer handed it over FIRE-relaxed or
pre-loaded. With `contact_semi_implicit` **off** the same comparison is 13 µm
and 0.019, so V3.2's scheme is doing exactly the job it was added for. A run
that ends AT a fixed point does not care that the rate was wrong; a compaction
run, whose whole answer is a rate, cares enormously.

So `auto` substeps **when cells are seeded and not otherwise**, and that is a
measurement rather than a guess.

### Why the controller is not the energy

The obvious signal, and the one asked for, was the energy. It cannot be used,
for a specific reason: **where `dt` matters is exactly where the V3.5 energy
audit is invalid.** With cells seeded, monotone descent is false because bridges
are actuators, so `energy_delta` cannot separate "`dt` too large" from "the
cells did work". And in the passive case, where the audit *is* exact, `dt = 0.5`
is already accurate to 0.05 %. The energy monitor stays the verifier; `S` is the
controller — and `k` is already computed every step for the semi-implicit
denominator, so `k/gamma` (units 1/h, free of `dt`) costs nothing.

### The design

`dt` becomes the interval at which the run is **sampled** — history, snapshots,
console — and `advance()` advances the mechanics inside it in `n_sub` substeps.
A substep is an **ordinary `step` with a smaller `dt`**, not a special
mechanics-only path, because everything inside `step` is already a rate times
`dt`: bridge formation is `1 - exp(-rate dt)`, the cell clocks are `+= dt`,
migration is `speed dt`, the active noise is `sqrt(2 gamma T / dt)`, a new
bridge's maturity is `dt / t_form`. All of those compose under subdivision. The
substeps are not an approximation of the outer step; the outer step was the
approximation.

No ramp: the rate is a **p95**, not a max, so one transient contact cannot move
it and there is nothing for a growth clamp to protect against. The controller is
seeded from the `t = 0` evaluation so the first interval is already sized.

### The second rail, and why `v_max` had to be scaled

Shrinking `dt` exposes a different rail: the absolute cap `v_max = 20 µm/h`
clips **36 % of granules at `dt = 0.02` and 49 % at `dt = 0.005`** where it clips
none at `0.5`, because the semi-implicit damping is no longer suppressing the
velocity — bridge forces of 180–440 nN on a drag of ~1 nN·h/µm want 180–440 µm/h.
A clipped granule has its force magnitude discarded. So `advance` scales `v_max`
with the subdivision: the cap limits **displacement per coupling interval**, not
speed per substep, and subdividing therefore cannot change how much force
information the cap discards. Measured: `frac_velocity_clipped` is **0.000** at
every substep count, against 0.49 at the equivalent fixed `dt`.

### The population rail

`v_max` is absolute and so must be set for the fastest thing the model can
produce, which makes it a force ceiling for everything slower. The relative rail
instead: a granule is capped at `dynamics.outlier_speed` times the median speed
of **its own coordination class** (contact count, capped at 6; a class with
fewer than `OUTLIER_MIN_CLASS = 8` members is not a population and is left to
`v_max`). We do not expect a granule to differ much from granules in its own
condition — and V3.5 measured one wedged granule at 132× the load while the
second-worst read 0.97×.

It is a guard, and the evidence says it behaves like one:

| | outlier rail fires | `v_max` fires |
|---|---|---|
| all four reference runs | **never** (bit-identical) | — |
| stiff PMMA cell bed | **0 %** | 0 % |
| loose shaped bed, no FIRE | up to 5.7 % (mean 1.3 %), `F_max` 3783 → 3005 nN | 37 % |
| noisy cell bed, `T_active = 5` | up to 11.4 % (mean 2.3 %) | **0 %** |

The last row is the case for it: it catches granules the absolute cap misses
entirely. On the reference runs it declines because those beds are too small for
any coordination class to be a population, which is the correct answer.

### Tests — `tests/test_substep.py` (25)

The number and that it really is that large; the controller's arithmetic, its
budget flag, and `auto`'s load test; `advance` with one substep bit-identical to
`step`, and `p.dt` / `p.v_max` restored even after a failure; the `v_max` scaling
against the fixed-`dt` twin; the convergence direction; and the population rail
— planted outlier caught, uniform population untouched, class at rest never
clipped, small class declined, off bit-identical, and the two rails never
double-counting.

## Phase 3 — cell types, traction as a stress, cell strain energy

Also not in the version as planned. Added on the request that cells should build
strain energy from the motor-clutch model and from bridge stretch, with the
contact area giving the traction stress, and that cell types should be
instantiable objects so fibroblasts can be swapped for something else.

### `gels/celltypes/`

A `CellType` is a frozen dataclass of `Measured` values — each a number, its
units, **its source**, and the range the source reports. There is no way to add
a value without saying where it came from; `source='ASSUMPTION'` marks a
calibration target and `report()` counts them.

Two types, and the second one is the point: an interface with one implementation
is a guess. `fibroblast` is the only one through the review in
`CodeLog/References/fibroblast_parameters.md`; `msc` says so in its own report.

`to_overrides()` emits dotted overrides in the same currency as a preset, so a
preset states the **scaffold** and a cell type states the **cell**, applied
after `--preset` and before `--set`.

### Traction as a stress over the contact area

`F = sigma x A_adhesion`, with `A_adhesion = adhesion_area_frac x
A_projected(spread_fraction)` — so the ceiling **grows as the cell spreads**
rather than being a number chosen per run.

The one thing the reference file explicitly forbids (section 2, item 3) is a
**density-independent** adhesion stress: `sigma_FA = rho_bond F_b plog(gamma/e)`
scales with engaged-bond density. So `cells.traction.stress_Pa` is the value at
saturating ligand, and the engine multiplies it by the Langmuir gain `g` and the
clutch engagement fraction before use. `test_it_scales_with_the_ligand_gain_not_with_nothing`
is that constraint as a test.

The self-consistency check every type must pass: `sigma x A` has to reproduce
the **independently measured** whole-cell traction. Fibroblast: 4 nN/um^2 x 0.08
x 1257 um^2 = 366 nN against Gaudet 2003's ~400 nN (ratio 0.91). That check is
what sets the adhesion area fraction, which is otherwise the weakest number in
the type — and it caught the first `msc` draft at a ratio of **2.85**.

### The negative result, pinned

**At the fibroblast's own numbers the ceiling never binds.** On 10 kPa, 50 kPa
and PMMA, at 1, 2, 4 and 8 h, `F_mean` is bit-identical with it on and off. The
two ramp together: the motor-clutch force carries `fa_maturity`, the ceiling
carries `spread_fraction`, and at full spread the adhesion holds 366 nN while
the motors deliver at most 182 nN even on a rigid granule.

That is not a wasted model. It says `F_max_per_cell = 150-200 nN` is a
**physically reasonable** cap rather than an arbitrary one — the cell pulls at
about half its adhesion's capacity — and it identifies `adhesion_area_frac` as
the knob that would make the adhesion the limit.

### Cell strain energy

A loaded cell is a spring in series with what it grips: `1/k = 1/k_cell +
1/k_sub`, and a bridging cell grips two, so its series includes both granules.
`U = F^2/2k`. Costs one pass over the per-cell force arrays the force evaluation
already fills, and no kernel change.

This is the quantity **traction force microscopy reports**, so it is a direct
comparison with experiment the model did not previously offer. `energy_cell`
joins the V3.5 audit: it is real stored energy, so leaving it out charged it to
the residual. It does **not** make the system conservative — a bridge is an
actuator and changes its own rest length — what it does is separate the
recoverable part, leaving `energy_residual` measuring the myosin work.

A prediction that could have been wrong and was not: on a granule stiffer than
~50 kPa the **cell** is the soft element, so `U` barely moves with granule
modulus (8203 vs 8001 nN.um between 10 kPa and rigid).

### What the instrumentation says about the model

Recorded, not tuned away. On a 24 h 2D bed with `--cell-type fibroblast`:

| | model | fibroblast on flat TFM |
|---|---|---|
| strain energy per loaded cell | **0.044 pJ** | 0.1-10 pJ |
| footprint traction stress | **21.8 Pa** | ~300 Pa (Gaudet 2003) |
| adhesion traction stress | 272 Pa | 0.5-2 kPa mean at adhesions |

About 10x low, consistently. That is now a visible calibration target rather
than an invisible one, and it is the first thing Phase 3 hands to the next
round of work.

And the abstraction does something: fibroblast vs MSC on the same bed gives
`disp_func` 54.4 vs 39.0 um and 90 vs 107 bridges — a different cell makes a
different scaffold.

### Tests — `tests/test_celltypes.py` (30)

The registry; every value has a source; the report flags assumptions and
out-of-range values; `sigma x A` against the measured whole-cell traction for
every type; the type's geometry against the engine's to 9 places; every override
is a real config key; the ceiling grows with spread, scales with `g`, and never
raises a force; the kernel leaf against the reference leaf on identical
arguments (**not** by comparing two runs — bridging is statistically equivalent
between the twins, not identical); `U = F^2/2k` by hand; the soft-element
prediction; the negative result above; and the default being off.

## Phase 4 — cells crawl on cells

Carried over from the V3.3 plan's Phase 5, whose analysis stands. The physics,
stated so it is falsifiable: a cell's anchorage is the **existing**
motor-clutch expression evaluated on whatever it stands on.

* layer 0 — `E = gs.E_gran[i]`, `nu = gs.nu_gran[i]`, `g = traction_gain(...)`;
* layer ≥ 1 — `E = cell_substrate_E`, `nu = cell_substrate_poisson`,
  `g = traction_gain(...) * anchor_gain(f_cell_cell, ...)`.

That substitution **is** the feature. The granule preference is a consequence.

**The trap, restated because it is easy to get wrong:** `g` enters
`motor_clutch_force` twice — as a prefactor *and* inside
`k_sub / (k_sub + g k_opt)` — so `F * h != F(g * h)`. The cadherin factor must
be folded into `g` **before** the call, never multiplied onto the result.

**State: one new per-cell array, `cell_layer` (int8), and no host-cell pointer.**
An absolute cell index would be invalidated by `add_cells`' CSR rebuild, and no
physics needs it: the substrate is a *material*, not a particular neighbour, and
bridge force already accumulates onto the host granule's row, so a stacked cell
correctly pulls its granule *through* the cell beneath.

Predicted effect at the defaults (`k_opt = 375 nN/µm`, `a = 10 µm`):
traction ratio cell/granule ≈ **0.178**, *falling* as granules stiffen (0.109 at
50 kPa, 0.091 on PMMA). **Stiffness does ~91 % of the work** — `f_cell_cell = 1`
alone moves the ratio only 0.178 → 0.196 — so the parity test must set **both**
E and f to parity, or it proves nothing.

**The safety property, and it is an `assert_array_equal`, not a statistic:** with
stacking **on** and the substrate at parity (`substrate_E = E_gran`,
`substrate_poisson = nu_gran`, `f_cell_cell = 1.0`), the run is bit-identical to
the stacking-off run — `anchor_gain(1.0) = 1.0`, the layer contrast is exactly
0, no RNG draw is consumed, and the reconciliation pass reduces to today's rank
rule.

5 new fields under `cells.stacking`; new preset `stacked_monolayer`.
Touches **three** cell paths — `reference.py`, `kernels/cells.py`, and the hybrid
`kernels/bridging.py` — plus `division.py` (daughters inherit `cell_layer`, read
**before** `add_cells`) and the three hand-written snapshot lists.

## Phase 5 — convergence detector

New `gels/convergence.py`, consuming the flat metrics dict only, so it imports
nothing from `gels.engine` and is usable from `pipeline/`, `tests/` and the
engine alike.

Signal mapping (all of these now exist — V3.3 Phase 2 landed them):
`gran_lf_func` (**not** `func_lf`, which moves with the tanh halo and with
`Ngrid`), `demix_phi_loc`, `n_contacts_if / n_contacts`, `F_mean`,
`n_bridging_cells`.

Two guards beyond flatness:
* **division rate** — differentiate `n_divisions_cum`. A constant division rate
  is not steady state. Pinned at 0 with division off, so it costs nothing.
* **functional-phase compaction** — `compaction_func >= 0.97` **and**
  `|d phi_loc_func| < eps`. `compaction_func` is `phi_loc_func / phi_RCP` from
  `gels/laguerre.py`, so `conv_enable` must imply `metrics_laguerre`. Do **not**
  fall back to `compaction_ratio`: it is halo-inflated ~1.5×, so a 0.97
  threshold against it is meaningless.

**Path length** is the signal history cannot supply — `disp_func` / `disp_inert`
are *net* displacement and cancel under creep. Compute it in the detector at
**save resolution** from the observer's snapshot, deliberately: it makes the live
detector and the shadow harness compute the *identical* signal, so a tolerance
calibrated in shadow is valid live.

**The design claim, and the test that can falsify it:** a power-law series
`x(t) = x_inf - a t^-0.3` must **never** converge over 50 proportional windows.

Default **off**. Calibrate with `pipeline/shadow_check.py` against `results/`
*before* enabling. Every stop writes a restart-complete frame, so a wrong
tolerance costs compute, never data.

## Non-negotiables (V3.5 rules, unchanged)

- One gate: `tests/test_identity.py` against a baseline blessed from the current
  tree. A behaviour change is **re-blessed, not pinned around** — and recorded in
  the changelog, because after re-blessing the gate can no longer see it.
- `reference.py` may change, but only **together with** the kernel twin it is the
  oracle for, in the same commit, with the `*_vs_reference` test as the proof.
- Metric keys land in **both** twins, as plain finite floats.
- A new `Params` field costs 5 places: dataclass, section dataclass, `FLAT_MAP`,
  `TEMPLATE_YAML`, optional `validate()` rule.
