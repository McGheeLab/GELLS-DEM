# V2.5: Stochastic Contact-Network Model

## Motivation

We need a mesoscale model that sits between the full DEM (`new_dem_0.py`, hours per run)
and the mean-field ODE (`analysis/mean_field_model.py`, milliseconds but no spatial info).

**Target**: Seconds per realization, 1000 Monte Carlo realizations in minutes.

## Literature Basis

The model combines three established approaches:

1. **Gillespie / BKL algorithm** (Bortz, Kalos & Lebowitz 1975; Gillespie 1977)
   - Exact stochastic simulation of continuous-time Markov processes
   - Bridge formation/dissolution are already Poisson processes in the DEM
   - Rejection-free: every step advances the system, with physical time

2. **Bond percolation on contact graphs** (Braz & Araujo 2022, 2025; Newman & Ziff 2001)
   - Ranked percolation on DEM-generated contact networks
   - Critical connectivity z_c ≈ 1.5-2.0 bonds/particle for system-spanning clusters
   - Union-find data structure for O(N) percolation tracking

3. **Rigidity percolation** (Petridou et al. 2021, Cell; Colombo & Del Gado 2024, PNAS)
   - Fluid-to-solid transition when bridge network becomes rigid
   - Elastic modulus: G ~ (z - z_c)^f with f ≈ 1.4
   - Predicts when scaffold can bear load collectively

4. **Spring network relaxation** (Ostoja-Starzewski 2002; Picu 2011)
   - Nodes = granule centers, springs = contacts + bridges
   - Overdamped relaxation: γ dx/dt = ΣF
   - O(N) per step with sparse iterative solvers

## Architecture

```
analysis/contact_network_model.py
├── NetworkParams (dataclass)        — mirrors relevant Params fields
├── Granule (dataclass)              — position, radius, type, cells
├── ContactGraph                     — adjacency, edge attributes
├── GillespieEngine                  — event catalog, SSA stepping
├── SpringRelaxation                 — overdamped network solver
├── PercolationTracker               — union-find, cluster stats

│   ├── from_params(p)               — construct from DEM Params
│   ├── from_packing(x, y, r, ...)   — construct from existing packing
│   ├── solve(t_total, seed)         — run one realization

└── Plotting functions               — compaction, percolation, clusters
```

## Algorithm

### Phase 1: Packing Generation (or Import)
- Simplified sphere-only RSA + inflate-relax (no superellipsoids needed)
- Or import packing from a DEM snapshot
- Build Delaunay triangulation → contact graph

### Phase 2: Cell Initialization
- Distribute cells on functional granules (same rules as DEM)
- Initialize cell states: ATTACHED → SPREADING → PROLIFERATING timeline

### Phase 3: Gillespie Event Loop
Events with rates:
1. **Bridge formation** (per eligible cell-pair):
   `λ_form = bridge_attempt_rate × path_factor(gap) × secondary_boost`
2. **Bridge senescence** (per active bridge):
   `λ_senes = 1/bridge_senescence_time` (unless locked in)
3. **Bridge rupture** (per stretched bridge):
   `λ_rupture → ∞` when gap > bridge_break_gap (instantaneous)
4. **Cell state transitions**:
   `λ_spread = 1/t_spread_duration`
   `λ_mature = fa_maturation_rate`

At each Gillespie step:
1. Compute total rate R = Σ λ_i
2. Select event i with probability λ_i / R
3. Execute event, advance time by dt = -ln(u)/R
4. Update affected rates in the event catalog

### Phase 4: Mechanical Relaxation (batched)
Every Δt_relax (e.g., 0.5h):
- Compute spring forces: JKR contacts + bridge traction
- Overdamped update: Δx = (ΣF / γ) × Δt_sub
- Iterate until force residual < tolerance
- Update contact graph (new/lost contacts from displacement)

### Phase 5: Observable Tracking
At each save point:
- x_f (functional zone fraction) — comparable to mean-field
- Percolation: largest cluster, spanning probability
- Coordination: mean Z, bridge Z
- Compaction ratio, porosity, permeability (Kozeny-Carman)
- Cluster size distribution

## Key Simplifications vs Full DEM

| Feature | Full DEM | Contact Network Model |
|---------|----------|----------------------|
| Granule shape | Superellipsoids | Spheres only |
| Contact detection | Newton-Raphson iterative | Analytic sphere-sphere |
| Force integration | Per-timestep (dt=0.5h) | Batched relaxation |
| Cell tracking | Individual per-cell arrays | Per-granule aggregates |
| Bridge formation | Per-cell Poisson | Per-edge Gillespie |
| Field rendering | 200² or 80³ grids | None (point-based) |
| Rotational dynamics | Quaternions | None (spheres) |
| Output | Full snapshots + fields | Scalar time series |

## Expected Performance

- 500 granules, 72h simulation: ~0.5-2 seconds per realization
- 1000 Monte Carlo realizations: ~10-30 minutes
- Memory: ~10 MB per realization (positions + graph + time series)

## Validation Strategy

1. Compare x_f(t) trajectory against full DEM runs
2. Compare percolation threshold against DEM bridge network analysis
3. Compare compaction kinetics (half-time, final density) across parameter space
4. Verify mean-field limit: ensemble average should approach ODE solution
