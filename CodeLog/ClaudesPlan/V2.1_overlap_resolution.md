# V2.1: Post-Step Overlap Resolution (Granule Pass-Through Fix)

## Problem

Granules can "pass through" each other during simulation (especially at t≈3-7h when bridge
forces mature). Root cause is three interacting factors:

1. **Sharp contact threshold**: Contact detection returns `None` (no force) when overlap ≤ 0
2. **Large timestep**: dt=0.5h → max displacement = v_max × dt = 10 µm/step per granule
3. **Global v_max cap**: Two approaching granules can close 20 µm/step combined

When bridge forces pull two granules together and the step overshoots the contact zone,
the contact detector sees no overlap → no repulsive force → granules continue into each
other → eventually one gets "swallowed."

## Solution: Position-Level Overlap Projection

Add a **post-integration overlap correction** to `step()`. After positions are updated from
velocities, check all pairs using bounding-sphere distances and push apart any that exceed
a maximum allowed overlap fraction.

This is the same approach used in the packing settle phase (`_settle_packing_3d`), extended
to the main simulation loop.

### Algorithm

```
After position update + boundary handling:
1. Build cKDTree from current positions (periodic-aware)
2. Query all pairs within cutoff = 2 * max(r_bound)
3. Compute overlap = r_bound[i] + r_bound[j] - dist(i,j)
4. For pairs where overlap > max_overlap_frac * min(r_bound[i], r_bound[j]):
   a. excess = overlap - threshold
   b. Push each granule apart by excess/2 along contact normal
5. Re-apply boundary handling (wrap/clip)
```

### New Parameter

- `Params.max_overlap_frac`: float, default 0.15 (15% of smaller bounding radius)
  - Normal Hertz deformation is ~1-5% of R, so 15% is generous
  - Prevents deep interpenetration without interfering with normal contact mechanics
  - Set to 0.0 to disable (not recommended)

### Performance Impact

- One extra cKDTree build + query_pairs per timestep (same as existing neighbor search)
- Vectorized numpy operations for correction
- Negligible compared to existing force computation (which already builds a tree)
