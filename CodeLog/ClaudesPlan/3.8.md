# V3.8 — the cell's search has a persistence time, not a timestep

## Why this version exists

The user asked whether `cell_sense_distance` could be set from the random search
distance a cell covers in `dt`, since 80 µm is asserted rather than derived.
Chasing that turned up something worse in the mechanism the question was about.

**The cell's random walk on the granule surface is scaled ballistically.**
[reference.py:379](gels/kernels/reference.py#L379):

```python
sigma = p.cell_migration_speed * p.dt / r_eff
```

`v·dt` is a *ballistic displacement* being used as the standard deviation of a
*diffusive* increment. Variance adds, so over a window `T` taken in steps of
`dt` the net angular spread is

    sigma_total = (v / r) * sqrt(T * dt)

which **depends on the timestep**. A random walk composes under subdivision only
when `sigma ~ sqrt(dt)`; this one is `~ dt`.

V3.6 made that bite. `dt` became a coupling interval and `advance()` subdivides
it 129–330× on the flagship fibroblast preset, so the search shrank by
`sqrt(n_sub)`. Measured, with division off so the CSR indices are stable, over
one coupling interval:

| T = 0.5 h | RMS \|Δθ\| | arc | predicted |
|---|---|---|---|
| `substep: off` (n_sub = 1) | 0.382 rad | **17.0 µm** | 0.337 |
| `substep: auto` (n_sub = 129) | 0.033 rad | **1.45 µm** | 0.030 |
| | | **11.75× suppressed** | √129 = 11.4 |

This was invisible because V3.6 re-blessed the baseline, which is exactly the
cost the V3.5 "re-bless, don't pin" rule accepts — so the changelog has to say
it out loud.

The sharp statement: **the model's persistence time is currently whatever `dt`
happens to be.** Setting `sigma = sqrt(2 D dt)/r` with `D = v² τ_p / d` recovers
today's un-substepped numbers exactly at `τ_p = 0.5 h`, because `τ_p = dt` is
what the old form implied.

## What `cell_sense_distance` turned out to be

Worth recording, because it redirects the original question. `sense_distance` is
tested against `gap` — the surface-to-surface void between two granules — at
four sites, so it **is** the void-spanning range the user remembered. But it is a
hard cutoff sitting on top of `exp(-gap / bridge_decay_length)` with
`bridge_decay_length = 30 µm`. At the fibroblast's 80 µm the path factor is
already `e^(-8/3) = 7 %` of its contact value, so the cutoff does very little
and **`bridge_decay_length` is what actually sets the range**. Deriving
`sense_distance` from search would have been tuning the wrong knob.

The cell's *reach* is the right meaning for it (the user's own framing: reach
sets the maximum search distance), and that is what it already claims to be.
Left alone this version.

## Locked decisions

| Decision | Choice |
|---|---|
| Persistence time | A **required** `Measured` field on `CellType` — no default, so no type can exist without stating one. Fibroblast **1.0 h** |
| Walk model | Persistent random walk: a heading that diffuses, a step that is `v·dt` along it. Correct in BOTH limits (ballistic for `dt << τ_p`, diffusive for `dt >> τ_p`) and composes exactly under subdivision |
| Crowding | **Mean-field occupancy**, `v_eff = v·[(1-θ) + θ·p_climb]` with θ from the per-granule aggregates that already exist |
| Climbing | `p_climb` derives from **`f_cell_cell`** — the same parameter that sets V3.6's 0.178× stacked traction, so one number governs both how hard a stacked cell pulls and how willing a cell is to climb |
| `sense_distance` | Unchanged. It is a reach, and the range is set by `bridge_decay_length` anyway |

## Phase 1 [DONE] — the persistent random walk

Pure diffusion (`sigma = sqrt(2 D dt)/r`) would be `dt`-independent but gives the
long-time answer at all times: at `dt = 0.5 h` and `τ_p = 1 h` it predicts 30 µm
of search where the true persistent walk gives 13.9 µm, because `dt < τ_p` is
the *ballistic* regime. And the substeps run at `dt/n_sub << τ_p`, which is
deeper into it. So the walk carries a heading:

* **3D** (the granule surface is 2-dimensional): heading angle `phi` in the
  tangent plane diffuses, `phi += N(0, sqrt(2 dt / τ_p))`, and the cell steps
  `v·dt` along `(cos phi, sin phi)` in `(eta, omega)`.
* **2D** (the surface is the 1-dimensional circumference): a telegraph process —
  the heading sign flips with probability `1 - exp(-dt / τ_p)` and the cell steps
  `v·dt·sign / r`.

Both give `MSD(t) = 2 d D [t - τ_p (1 - e^{-t/τ_p})]` in the continuum limit, and
both compose under subdivision: the heading update is the only random term and it
has the `sqrt(dt)` scaling, while the displacement is a rate × dt.

One new per-cell array, `cell_heading` (float64), wired exactly as V3.6 wired
`cell_layer`: `CELL_ARRAYS`, the three hand-written snapshot lists
([engine.py:7172](gels/engine.py#L7172), [:7566](gels/engine.py#L7566),
[:7654](gels/engine.py#L7654)) in the **unconditional** block, and both twins.

## Phase 2 [DONE] — mean-field crowding

`v_eff = v · [(1 - θ) + θ · p_climb]`, the standard lattice-gas mean-field
mobility for simple exclusion, with θ the granule's occupancy
(`n_attached / capacity` — both already computed) and `p_climb` from
`f_cell_cell`.

At θ = 0 it is exactly the uncrowded walk, which is the parity test. At θ = 1 the
mobility is `p_climb`, i.e. a cell on a full granule can only move by climbing.

## Phase 3 [DONE] — tests and documentation

New `tests/test_cell_walk.py`. The load-bearing cases:

* **`dt`-independence** — the same run under `substep: off` and `substep: auto`
  must give the same RMS search distance. That is the bug, and the gap is 11.75×
  today. Division must be OFF in the test, because `add_cells` rebuilds the CSR
  and an index-wise comparison across it silently compares different cells (this
  cost a wrong measurement during planning, twice: once to that and once to
  `pi/sqrt(3) = 1.8138`, the uniform-circle saturation value, which makes any
  long-window RMS look identical).
* both limits: ballistic for `dt << τ_p`, diffusive for `T >> τ_p`;
* crowding parity at θ = 0;
* every cell type states a persistence time (the required-field test).

**The baseline must be re-blessed**, and the changelog must say what changed and
why, because after re-blessing the gate can no longer see it.

## Landed beyond the plan

**A crowding diagnostic.** `cell_occupancy_mean` and `cell_crowd_mobility`, so a
run says whether crowding is binding rather than silently scaling the search.

**The initial heading is randomised at seeding.** `CELL_ARRAYS` gives every new
slot a constant, so without this every seeded cell set off the same way — in 2D
that is every granule's cell ring rotating together for the first ~`tau_p`.
Randomised in the V3.2 "desynchronise the population" block, from a SPAWNED
child stream -- taking it from `rng` broke the contract that seeding consumes
exactly the surface-angle draws when division is off, and moved the seeded
cell-age CV from 0.577 to 0.706. The suite caught it; the spawn costs the
packing nothing. Daughters still inherit the default, which is
harmless: division is a trickle rather than a cohort, and a heading decorrelates
within `tau_p`.

## Measured

| | before | after |
|---|---|---|
| search over 0.5 h, `substep: off` | 17.0 um | 10.8 um |
| search over 0.5 h, `substep: auto` (n_sub 129) | **1.45 um** | **9.2 um** |
| off / auto ratio | **11.75x** | **1.175x** |

The shipped configuration is `substep: auto` with cells seeded, so the search
distance a real run gets rises about **6x**. The `off` column falls because the
mean-field crowding now reduces mobility (about 0.58 at the seeded occupancy),
which is a new effect rather than a correction.

## Still open (not tasks)

* **`tau_p = 1.0 h` is the short end of Gail & Boone.** Their data show
  persistence across 2.5 h intervals. `D = v^2 tau / 2` is linear in `tau`, so
  the span (0.5, 3.0) is a factor of 6 in diffusivity. Worth a sensitivity run
  before quoting any search-limited result.
* **`msc`'s persistence time is the fibroblast value borrowed wholesale.** Like
  the rest of that type, it needs its own review.
* **`p_climb = f_cell_cell` is an identification, not a measurement.** It is
  defensible (both are "how much does a cell like a cell surface relative to a
  granule") and it usefully couples two observables to one parameter, but
  nothing has been measured that says the climbing probability equals the
  cadherin coverage.
* **The residual 1.175x** is the coarse resolution of the heading process at
  `dt/tau = 0.5`. The substepped answer is the converged one. A run that cares
  about the search specifically should check convergence in `dt`.
