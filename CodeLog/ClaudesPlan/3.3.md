# GELLS-DEM V3.3 — adopt robotsim's physics/metrics machinery + cell stacking

## Context

`robotsim/` is a gitignored sibling repo attacking the same physics from the opposite end
(explicit surface agents vs. a contact-level cell kernel). `robotsim/docs/gells-dem-adoption.md`
records what robotsim should borrow *from* GELLS. This plan is the reverse direction, which
has never been written down: what GELLS should borrow from robotsim.

A comparison of the two trees found eight adoptable items plus one genuine capability gap.
Two measurements taken during planning make the case sharper than expected:

1. **The superellipsoid contact solver is broken, not merely approximate.** At 2 % past first
   touch, `find_contact_superellipsoids_3d` ([engine.py:3095](gels/engine.py#L3095)) detects
   **25/200 = 12 %** of true contacts, and over-reports penetration by **median 9.8×, p90 43×**
   on the ones it finds (verified twice, independently). This corroborates the KNOWN BLOCKER
   at [CHANGELOG.md:97-133](CodeLog/Updates/CHANGELOG.md). The cause is structural: `delta` is
   set to `dp_mag` — the *distance between two common-normal surface points* — not a
   penetration depth, and the normal is `(p_j − p_i)/|·|`, not a surface normal, so the force
   is not the gradient of any energy.
2. **The support function of GELLS's anisotropic two-exponent superellipsoid is closed form.**
   Inverting `superellipsoid_normal` ([engine.py:1278](gels/engine.py#L1278)) gives a nested
   dual norm:

   `h(n) = ‖( ‖(a·nₓ, b·n_y)‖_q₁ , c·n_z )‖_q₂`,  `q₁ = n₁/(n₁−1)`, `q₂ = n₂/(n₂−1)`

   Verified against a 600×1200 brute-force surface max: **4.9e-6 relative** (mesh-limited) for
   random `n₁≠n₂`, and **3.6e-15** at the sphere anchor. This is the exact generalisation of
   robotsim's superball-only `h(n) = R‖Rᵀn‖_q` ([superquadric.py:26](robotsim/code/superquadric.py#L26)),
   so the whole minimum-translation-distance (MTD) formulation ports — it is *not* limited to
   equal semi-axes.

Outcome: a contact solver whose forces are conservative by construction, structural metrics
that measure the real contact graph instead of a halo-inflated render, optional early stopping,
and cells that stack with an emergent preference for the granule surface.

## Phase 1 — neighbour correctness (min-image guard + Verlet list)

**Guard.** The cutoff `2·max(r_bound) + p.L_max` ([contact3d.py:332](gels/kernels/contact3d.py#L332),
[contact2d.py:349](gels/kernels/contact2d.py#L349), [reference.py:1395/1762](gels/kernels/reference.py#L1395))
goes straight into `cKDTree(boxsize=…)` with no check. Verified: scipy raises nothing for
`r > L/2` and returns each pair **at most once**, so a contact is silently **dropped**, not
double-counted. Port the inequality only from
[gel3d.py:189](robotsim/code/gel3d.py#L189) — drop its `(phi_worst/phi0)^(1/3)` factor, which
exists because robotsim compresses its box and GELLS does not.

Three layers, all periodic-only (walls/cylinder are exempt — no images):
- `validate()` rule in [config.py:859](gels/config.py#L859), using a species-moment estimate of
  `r_bound` in the style of `shape_bound_factor` ([engine.py:3628](gels/engine.py#L3628)).
- Runtime raise in `run()` after packing ([engine.py:5056](gels/engine.py#L5056)) on the true
  `max(gs.r_bound)` — this is the layer that guarantees correctness.
- Fix [neighbors.py:184-186](gels/kernels/neighbors.py#L184): `min(ncs) < 3` fires at
  `cutoff > L/3` and *defers to the tree* in precisely the regime where the tree drops pairs.
  Split it — raise at `cutoff >= 0.5·min(box)`, keep the tree fallback for `L/3 < cutoff < L/2`.
  Put the raise in `half_pairs` ([neighbors.py:210](gels/kernels/neighbors.py#L210)), the funnel
  both backends share.

**Verlet list.** Implement the `2·max_disp ≥ skin` rebuild that
[engine.py:328](gels/engine.py#L328) already documents. Two hard requirements:

1. **Bit-identity, because Gate B cannot be avoided here.** The stored fixtures contain
   `perf_neighbor_skin: 20.0`, and `test_step1_params_json_identical` compares stored values —
   so the fixtures *will* exercise the skin path and must produce identical results. This is
   achievable and is the design constraint: the list holds pairs within `cutoff + skin`, which
   is a **superset**; contacts are filtered on actual overlap every step, so extra pairs
   contribute exactly zero; and the list must be emitted in the **same sorted order** as today
   so float summation order is unchanged. Gate B is itself the test.
2. `cutoff + skin < L/2` — the skin widens the surface Phase 1 just closed, so the guard must
   be applied to the *inflated* cutoff.

Twin parity requires both twins to rebuild on the **same steps**, so the trigger must be
computed identically in both.

**Tests** — new `tests/test_min_image.py`: the dropped-pair regression (L=10, points at x=1 and
x=9, cutoff 8 — brute-force 27-image finds 2 interactions, `query_pairs` returns 1); the raise
fires for both backends; `validate()` names the failing axis; walls/cylinder/free-top pass.
Plus a Verlet test that a rebuild-every-step run and a skinned run agree bit-for-bit.

## Phase 3 — MTD contact solver (the load-bearing phase)

Work order is deliberately **plumbing-before-physics**, with a checkpoint that proves the
plumbing is inert before anything moves.

| Step | Work | Gate |
|---|---|---|

Returns `(h, ∇h, η, ω)` — the inversion is free from the same intermediates. Register in `_warmup_jit` ([:4935](gels/engine.py#L4935)). No call sites touched. | `tests/test_support_function.py` |
| 3.2 | MTD kernels in both twins + Optional-returning wrappers in `engine.py`. **Same tuple widths** as today, so the 8 call sites change by one `if`, not a rewrite. | `tests/test_mtd_contact.py` |
| 3.3 | Params/config ×5 places; thread `solver_code` into **all 8** call sites. Flag still defaults to `common_normal`. **Run Gate A + Gate B — everything must still be bit-identical.** | Gates A + B |
| 3.4 | Flip default to `mtd`. Pin `contact_solver='common_normal'` in `COMMON` ([make_fixtures.py:48](tests/make_fixtures.py#L48)) — *not* in `PARAMS_TRIALS`, which only feeds a key-wise comparison that never visits new keys. Add `--v33` mode writing to a **separate** `tests/fixtures_v33/` tree (appending to `REFERENCE_RUNS` would couple the two generations). | Gate B green with the pin |
| 3.5 | Walls via the support function; `contact.wall_torque` flag | `tests/test_wall_contact.py` |

**Mandatory implementation details:**

- **Max-factored norms, always.** Never evaluate `|Nx|**q` directly — at a≈40 µm and q=60 that
  is ~1e96 and the outer level overflows. Factor by the max so every base is in [0,1]; the
  gradient weights are then in [0,1] for free.
- **Degenerate cases:** `q = min(n/(n−1), 60)` for `n ≤ 1` (numerically the max-norm, the correct
  octahedral limit); `q = max(q, 1+1e-9)`; explicit `P = 0` branch for `n` along ±z; guard
  `h < 1e-300`. Do **not** replicate `_sgnpow`'s `+1e-30` bias
  ([engine.py:1246](gels/engine.py#L1246)) — it would break the exactness identity.
- **Separation certificate:** evaluate `sep(n₀)` first; `sep(n₀) > 0` *proves* separation and
  returns immediately. Neighbour lists are generous, so this rejects most candidate pairs in
  one evaluation — that is how the extra iterations are paid for. Today's solver runs 15
  unconditional iterations on every candidate.
- **Three seeds** (centre line + each body's best-aligned face column of R), keeping the best
  `sep`. Required for blocky shapes — flat faces stall a centre-line ascent on a ridge.
- **Allocation-free.** Today's solver allocates ~8 numpy arrays per iteration
  ([engine.py:3125-3159](gels/engine.py#L3125)); the MTD kernel must be pure scalars. Every
  early exit returns the literal-typed tuple or numba will not unify.
- **Truncation bias is safe:** `sep(n) ≤ sep(n*)` ⟹ a short ascent gives `δ ≥ δ_true`, i.e.
  slightly too stiff — bounded and continuous, never a missed contact. Assert the residual
  `|g⊥| < 1e-4·(r_i+r_j)` rather than widening the tuple with a `converged` flag.
- **`R_eff` becomes exact.** For a convex body the reverse Gauss map is `x(n̂) = ∇h(n̂)`, so the
  principal radii are the nonzero eigenvalues of `∇²h(n̂)`: `R_eff = sqrt(det ∇²h|_{n̂^⊥})`.
  Implement by central-differencing **∇h** (not the surface point) along two tangents at
  ε=1e-5 — accurate to ~1e-8 versus the current scheme's ~1e-2. This removes the fixed-step FD
  and the `max(κ,1e-6)` floor ([engine.py:1336](gels/engine.py#L1336)) at once. Applies to
  **both** solvers. Verified prerequisite: `superellipsoid_point(η*,ω*) == ∇ₙh(n)` to 4e-16.
- **De-duplicate `curvature_R_cap`**, currently copied four times with two different guards
  ([contact3d.py:90](gels/kernels/contact3d.py#L90) guards `R_eff>0`, [contact2d.py:96](gels/kernels/contact2d.py#L96)
  does not). One `@njit` leaf, unified on the 3D form.
- **Extend the `validate()` rule** at [config.py:985](gels/config.py#L985): `mtd` + shape_enabled
  + blockiness > 2.05 + `curvature_R_cap <= 0` is now an **error**. Under MTD, `R_eff` is the
  *true* ~1e15 µm curvature at a flat face rather than FD noise, so this combination is more
  dangerous than it is today.
- **Walls.** `penetration = h_i(−ŵ) − (c_i−q)·ŵ`, contact point `= c_i + ∇h_i(−ŵ)`. Replaces
  five brute-force samplers (20×20 in 3D, 64-point in 2D) and kills the unjustified hardcoded
  `R_local = r_bound·0.5`. Widen the wall status tuple (internal, not serialised). Support-function
  wall geometry rides with `solver == 'mtd'` to keep Gate B clean; `contact.wall_torque`
  (default `False`) is a **separate** flag and works on both solvers — `common_normal` uses its
  sampled extremum as the lever arm, which it already computes and merely discards.

**Both solvers stay first-class** (user decision): every new test case runs in both, and both
get exact `R_eff` and wall torque.

**Consequences to document, not to fix:**
- Shaped contacts become ~30× softer at shallow approach and 3–9× more numerous. This is the
  bug fix, not a regression.
- **MC-DEM effectively switches off for shapes**: `ε_V = Σδ/(2R)` ([contact2d.py:155](gels/kernels/contact2d.py#L155))
  drops ~10× with a true δ, so `κ → 1`. This is *correct* — MC-DEM was being driven by a 10×
  inflated strain. Spheres are unaffected (their δ was always right). Record κ before/after.
- `viz/stress.py` ([:255](viz/stress.py#L255)) magnitudes drop ~30× for shapes; make it read
  `p.contact_solver` rather than assume, and record the solver in `metadata.json`.
- `overlap_model: elastic` ([engine.py:1681](gels/engine.py#L1681)) is a sphere derivation that
  was never applicable to the shaped path; under MTD it becomes valid with **no formula change**.
  Add the test that was previously impossible: a single loaded contact's measured equilibrium
  overlap vs. the predicted `δ_eq` within 20 %.

## Phase 4 — FIRE post-settle relaxation

Hook after the post-relax loop in both twins ([packing.py:713-719](gels/kernels/packing.py#L713),
[reference.py:665](gels/kernels/reference.py#L665) and ~`:893`), entered only on
`relax_mode == 'fire'` so the default moves nothing.

**Reuse the settle's own force law**, not JKR — JKR is adhesive, so FIRE would pull the bed
together rather than relax it, and it would need `compute_forces_*` inside `packing.py`
(circular import). The settle's `k_rep·ov^1.5` is `−∇E` for `E = (2/5)k_rep Σ ov^2.5`; under
`packing_shape_contact` the directional-radius law's gradient was already verified as a true
energy gradient in V3.2 ([engine.py:1515-1521](gels/engine.py#L1515)). So FIRE replaces the
*dynamics* (capped overdamped Euler → inertial FIRE) and the *stopping rule*
(`max_overlap < tol` → `max|F| < f_tol`) on the same force. V3.3 relaxes **translations only**;
angular FIRE is V3.4.

**Do not touch the stateful scheduler.** FIRE takes a frozen `g_fire = sched.g_lo` and never
calls `sched.g()` or `sched.converged()`. The kernel calls them inline
([packing.py:695-697](gels/kernels/packing.py#L695)) while the reference computes a flag and
breaks later ([reference.py:623/658](gels/kernels/reference.py#L623)); any extra call
desynchronises the twins silently. Add a **call-count test** with and without FIRE.

**Project the velocity at every wall clamp**, not just the position — otherwise `P = F·v` is
polluted, FIRE's sign test misfires and the bed pumps against the wall.

Non-dimensionalise with `f_scale = k_rep·(0.05·mean_r)^1.5` so
[gel3d.py:134-137](robotsim/code/gel3d.py#L134)'s constants transfer unchanged.

Diagnostics → `metadata.json['packing']` (not compared by Gate B): `Z_nonrattler` (with
**iterative** rattler removal, unlike robotsim's single pass), `rattler_fraction`, `f_max`,
`fire_steps`, `fire_converged`, and `penetration_mean/p95/max` — the certificate that only
became computable once the MTD solver exists. Do **not** port the compression-to-φ_J loop
([gel3d.py:238](robotsim/code/gel3d.py#L238)); we are not targeting φ_J.

## Phase 5 — cells crawl on cells, with an emergent granule preference

**The physics, stated so it is falsifiable.** A cell's anchorage is the existing motor-clutch
expression ([engine.py:2554](gels/engine.py#L2554)) evaluated on whatever it stands on:

- layer 0: `E = gs.E_gran[i]`, `ν = gs.nu_gran[i]`, `g = traction_gain(…)` — *verbatim today*.
- layer ≥ 1: `E = cell_substrate_E`, `ν = cell_substrate_poisson`,
  `g = traction_gain(…) · anchor_gain(f_cell_cell, …)`.

That single substitution **is** the feature. The preference is a consequence, not a rule.

**Correction to the obvious approach:** `g` enters `motor_clutch_force` **twice** — as a
prefactor *and* inside `k_sub/(k_sub + g·k_opt)` ([engine.py:2589](gels/engine.py#L2589)). So
`F·h ≠ F(g·h)`; the cadherin factor must be **folded into `g` before the call**, never
multiplied onto the returned force. This is the same error class the docstring warns about at
[engine.py:2570-2571](gels/engine.py#L2570).

**Effect size at the defaults** (`k_opt = 375 nN/µm`, `a = 10 µm`, `κ = 0.213`):

| substrate | E (kPa) | ν | g | β = k_sub/(k_sub+g·k_opt) |
|---|---|---|---|---|
| granule, f=1 | 10 | 0.45 | 1.000 | **0.512** |
| granule, f=1 | 50 | 0.45 | 1.000 | 0.840 |
| PMMA, f=1 | 3e6 | 0.37 | 1.000 | 1.000 |
| **another cell** | **1.0** | **0.5** | **0.501** | **0.182** |

Traction ratio cell/granule = **0.178**, and it *falls* as granules stiffen (0.109 at 50 kPa,
0.091 on PMMA) — exactly the motor-clutch story. **Stiffness does ~91 % of the work**: setting
`f_cell_cell = 1.0` alone only moves the ratio 0.178 → 0.196, so the falsifiability test must
set **both** E and f to parity.

**State: one new per-cell array, `cell_layer` (int8), and no `cell_host_cell`.** A host-cell
pointer would hold an absolute cell index, which `add_cells` invalidates
([engine.py:710-727](gels/engine.py#L710)) — and no physics needs it: the substrate is a
*material*, not a particular neighbour, and bridge force already accumulates onto the host
granule's row ([reference.py:981](gels/kernels/reference.py#L981)), so a stacked cell correctly
pulls its granule *through* the cell beneath.

**Mechanism.** The preference cannot ride on the existing migration walk: there is no radial DOF
and `F_gran`/`F_cell` are per-granule, so a durotactic drift term on `θ`/`(η,ω)` would be
identically zero. Layer is the only axis along which the tractions differ. So:

- A **reconciliation pass** (deterministic, CSR rank as seniority) that promotes only, never
  demotes — this reduces *exactly* to today's `k >= effective_cap` rule when every cell starts
  at layer 0.
- A **relayering pass** driven by the bounded contrast `χ = (F_gran − F_cell)/(F_gran + F_cell)`
  — 0 at parity, sign gives direction, no ad-hoc clamp. At `r_relayer = 0.5/h` and χ = 0.70,
  mean descent ≈ 2.9 h per storey, so it genuinely competes with `overcrowd_senescence_time = 12 h`.
- **Draws a random number only when a branch is taken**, so at χ = 0 the RNG stream is untouched.

**No radial position offset in the physics.** It would change `_cell_world_pos_*` signatures in
the two hottest twins for one second-order term, and it conflates "stacked cells pull weaker"
with "stacked cells are further away" in the bridge gap decay. Instead write `cell_layer` to the
snapshots and give the renderer an optional layer offset so stacked cells *look* stacked.

**Division needs one change:** daughters inherit `cell_layer` from the parent on the same
granule (0 when colonising a bridged granule), read **before** `add_cells` per the CSR warning.

Touches **three** cell paths, not two: [reference.py](gels/kernels/reference.py) (the oracle —
append inside `if stack_enabled:`), [cells.py](gels/kernels/cells.py), and the hybrid
[bridging.py:86](gels/kernels/bridging.py#L86), plus [division.py](gels/division.py) and the
**three hand-written snapshot lists** ([engine.py:4493](gels/engine.py#L4493),
[:4868](gels/engine.py#L4868), [:4955](gels/engine.py#L4955) — put `cell_layer` in the
*unconditional* block, layers exist in 2D).

5 new Params fields: `cell_stacking_enabled` (False), `cell_substrate_E` (1.0 kPa),
`cell_substrate_poisson` (0.5), `f_cell_cell` (0.15 — an **assumption**, mark for calibration),
`cell_relayer_rate` (0.5/h). New preset `stacked_monolayer` (seeds above the monolayer so layer 1
exists at t=0; `fibroblast_realistic` alone never overflows).

**The safety property:** with the feature **on** and the substrate set to parity
(`substrate_E = E_gran`, `substrate_poisson = nu_gran`, `cadherin_coverage = 1.0`), the run is
*still bit-identical* to the feature-off run — `anchor_gain(1.0) ≡ 1.0`, `χ = 0.0` exactly, no
draw consumed, reconciliation reduces to the rank rule. That is the falsifiable statement of
the requirement, and it is an `assert_array_equal` test, not a statistical one.

## Phase 6 — convergence detector + shadow harness

New `gels/convergence.py`, consuming the flat metrics dict only (imports nothing from
`gels.engine`), so it is importable from `pipeline/`, `tests/` and the engine alike. Keep
robotsim's proportional windows verbatim — `[t/2, 3t/4)` vs `[3t/4, t]`
([convergence.py:113](robotsim/code/convergence.py#L113)) — and the `quiet or steady`
displacement test, whose "steady creep with flat structure is converged" argument transfers
exactly to a prestressed granular bed.

Signal mapping: `f_gel → gran_lf_func` (**not** `func_lf` — the grid version moves with the halo
and with `Ngrid`, so its flatness is partly a rendering artefact; this is why Phase 2a must
precede this phase); `demix → demix_phi_loc`; `z_fi → n_contacts_if/n_contacts`;
`P_vir → F_mean`; `drain → n_bridging_cells`.

**The two signals you asked for:**
- **Division guard** — differentiate `n_divisions_cum` (already in `m`). It is a *guard*, not a
  flatness test: a constant division rate is not steady state. With division off it is pinned
  at 0 and costs nothing.
- **Functional-phase compaction** — two required conditions: `compaction_func >= 0.97` (the
  ceiling) **and** `|Δ phi_loc_func| < ε` (not still rising). `compaction_func` is
  `phi_loc_func / phi_RCP` from Phase 2b, so this is one comparison. **`validate()` gains
  `conv_enable ⇒ metrics_laguerre`** — that rule is the entire justification for
  `metrics_laguerre` being a config field. Do *not* silently fall back to `compaction_ratio`;
  it is halo-inflated ~1.5×, so a 0.97 threshold against it is meaningless.

**Path length** (robotsim's `path_F/I`) is missing — `disp_func`/`disp_inert` are *net*
displacement and cancel under creep. Compute it in the detector at **save resolution** from
`on_save`'s `snap` (never None when an observer is attached —
[engine.py:5079](gels/engine.py#L5079)). Save resolution is the deliberate choice: it makes the
live detector and the shadow harness compute the *identical* signal, so a tolerance calibrated
in shadow is valid live.

**Resume:** history has no positions, so the monitor persists its own row buffer as
`convergence.json`, re-ingested via `load_rows` — which is what that method exists for.

**Config: 3 fields only** (`conv_enable`, `conv_shadow`, `conv_t_min_h`); the ~12 tolerances are
module constants with an `overrides: dict` escape hatch for the shadow sweep. `validate()` must
also check `save_every_h` yields ≥ ~20 rows by `t_min`, otherwise the detector **silently never
fires** (it needs `len(A) >= 2 and len(B) >= 2`).

**Observer composition** (`--live` + convergence): add `CompositeObserver` to
[observer.py](gels/live/observer.py) and one branch in `as_observer` — ~20 lines, no signature
change. `on_step` must **`or`-accumulate, not short-circuit** (`any(genexpr)` would stop calling
children after the first `True` and desynchronise the viewer's pause loop). Detector first,
viewer second. Let `run()` prefer an observer's optional `stop_reason` so `metadata.json`
distinguishes `converged` from `viewer_stop`.

**Shadow harness** → `pipeline/shadow_check.py` (an operator tool reading `results/`, not a
hermetic test). Replays `history.json` row by row; reconstructs path length from consecutive
snapshots; ports robotsim's proxy table for old runs missing the new keys and **refuses to emit
a tolerance recommendation from proxy-only runs**. Reports `saved_pct`, damage in
`gran_lf_func`/`phi_loc_func`/`n_bridges` after `t_stop`, and — not in robotsim, and the most
useful column — **`blocking_signal`**, the last signal to fail. `--sweep EPS_GEL=…` prints the
saved-vs-damage frontier.

**Critical test:** a power-law series `x(t) = x_inf − a·t^-0.3` must **never** converge over 50
proportional windows. That is the entire design claim.
