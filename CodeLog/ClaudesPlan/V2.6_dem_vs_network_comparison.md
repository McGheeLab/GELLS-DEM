# V2.6: DEM vs Contact Network Model Comparison

## Context
We have 20 DOE_3D runs (~hours each) and want to test if the stochastic contact network
model (~21s per 48h realization with 250 3D particles) can predict the same outcomes when
initialized from the **exact same** initial packing. This validates whether cheap network
models can substitute for expensive 3D DEM.

## Implementation: `viz/doe_dem_vs_network.py`

### Data flow (per DOE_3D point):
1. `load_run('results/LHC/DOE_3D_NNNN/')` → get DEM history + t=0 snapshot
2. Extract sphere arrays from snapshot: `x, y, z, r, gtype, n_cells`
3. **Deterministic**: `ContactNetwork.from_snapshot(snap, p)` → `net.solve(t_span=(0,t_max))`
4. **Stochastic**: `from_packing(pos, r, gtype, n_cells, p)` → `solve(model)` × N realizations
5. Compare all three time series (DEM, deterministic, stochastic ensemble)

### Key design: custom ensemble on fixed packing
The built-in `ensemble()` generates fresh packings per realization — we bypass it. Instead:
- Build model dict once from DEM snapshot via `from_packing()`
- Call `solve(model, seed=base+i)` N times (model is not mutated by solve)
- Compute ensemble statistics (mean, std, IQR) on common time grid

### Comparable metrics (DEM ↔ Network):
| Metric | DEM key | Stochastic key | Deterministic key |
|--------|---------|---------------|-------------------|
| Contacts | `n_contacts` | `n_contacts` | `n_contacts` |
| Bridges | `n_bridges` | `n_bridges` | `n_bridges` |
| Bridge force | `bridge_force_mean` | `F_bridge_mean` | `mean_force_bridge` |
| Permeability | `K_kozeny_carman` | `K_perm` | (via descriptors) |
| Porosity | `porosity` | `phi_v` | (via descriptors) |
| Coordination Z | 2×n_contacts/N | `Z_contact` | `Z` |
| Locked bridges | `n_locked_in_cells` | `n_locked` | `n_bridges_locked` |

### Network-only (DEM can't compute):
- `spanning` (bool), `largest_cluster`, `Z_bridge`, `bridge_fraction`

### Plot modules (5):
1. **Paired scatter** — DEM final vs Network final, 1:1 line + regression ± σ
2. **Time evolution** — DEM trajectories vs stochastic ensemble mean ± σ
3. **Predictability table** — R², slope, DEM/Net ratio, CSV + bar chart (green/orange/red)
4. **Network-only metrics** — percolation onset, cluster sizes, spanning probability
5. **Summary dashboard** — cost comparison + R² heatmap

### Bug fixes during development:
1. **Bridge exclusion cap**: Stochastic model produced ~200× too many bridges because
   `compute_bridge_rates()` didn't enforce the `bridge_exclusion_angle` spatial limit.
   Added per-edge cap: 3D = 2/θ², 2D = π/(2θ). For θ=0.8: max 3 per edge in 3D.
   Result: bridge counts within 30% of DEM.
2. **Periodic BC wrapping**: `ContactNetwork._rebuild_edges()` failed when positions
   drifted outside [0,L). Added modular wrapping before cKDTree construction.

### Known limitations:
- Network model uses **spheres only** (DEM has superellipsoids) → systematic shape bias
- DEM uses **periodic BCs**; stochastic model uses **wall BCs** → edge effects
- DEM `phi_f` is grid-rendered; network computes sphere-volume fractions → ~5% offset
- DEM tracks individual cells; network tracks aggregate per-granule cell count
- Bridge timing: network starts bridging ~2h later due to fa_maturity gating

### Runtime:
- 250 3D particles: ~21s per 48h Gillespie realization (was ~2.5s for 2D/43 particles)
- Deterministic model: ~1s per 48h solve
- 20 DOE × 10 ensemble ≈ 70 minutes total
